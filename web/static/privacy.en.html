1. Overview

__SITE_NAME__ ("we," "the Service") is committed to protecting your privacy. This Privacy Policy explains how we collect, use, store, and share your personal information, as well as your rights regarding that information.

This Service is a self-deployed open-source gateway tool. This Privacy Policy applies to all personal information collected and processed by the deployer-operator ("Operator") through this Service.

2. Information We Collect

2.1 Information You Provide

  • Discord Account Information: When you log in via Discord OAuth, we obtain your user ID, username, avatar, and guild membership information from Discord. This information is used to create and identify your account.
  • Dify App Configuration: The Dify App API address and API keys you configure on the platform. API keys are stored encrypted with AES-256-GCM.

2.2 Automatically Collected Information

  • Request Logs: For each API call, we record the time, model name used, service name, call status (success/failure), HTTP status code, and error code. Request/response content is handled according to the operating mode:
    • Normal Mode: Specific request/response content is not persisted to logs.
    • Administrator Debug Mode (-debug startup flag): Complete raw requests and mapped input fields are written to server disk (file permissions 0644), with no automatic cleanup; this mode is only available when explicitly enabled by the administrator for debugging purposes.
    • User Self-Service Debugging: Request content is streamed in real time to your browser via SSE within server memory, not written to disk, and automatically cleaned up when the page is closed.
  • Charity Settlement Records: When you use a charity model, we record internal links among the consumer, donation entry, and donor (if any), together with the settlement price and reward, state, and timestamps. These records support atomic charging, failure refunds, and crash recovery and do not contain request or response content.
  • User-Level Daily Activity Aggregates: For each UTC day, we record your API attempt count, API success count, successful console business-write count, check-in count, and update time to produce site-wide service-usage summaries. Administrators see only site-wide activity summaries, not active-user lists or individual filters.
  • Irreversible Site-Wide Anonymous Statistical Snapshots: For each completed UTC day, we retain counts of new users, distinct users in each activity category, API request volume, and rolling 7/28-day activity and engagement. A snapshot contains no user ID, Discord information, username, hashed or random user identifier, service, model, or other dimension that can identify or filter an individual. Related counts for fewer than five people are suppressed as <5 under a k=5 rule; exact request volume is not retained for those groups and suppressed values are not reconstructed through differences.
  • Technical Logs: Standard server logs (e.g., IP address, request time), used solely for operational troubleshooting and abuse prevention.

3. How We Use Information

  • Service Provision: Authenticate your identity and route your API requests to your configured Dify App.
  • Abuse Prevention: Request-frequency-based rate limiting and anomaly detection to protect service stability.
  • Operational Improvement: Analyze aggregated usage data to improve the Service.

3.1 Tiered Moderation and Data Visibility

The Service uses a user-level system (levels 1–5, see Terms §2.1) under which some users (moderators) gain visibility into other users' data, as follows:

  • Level 4 users: May view and review pending charity donation applications, including the applicant's submitted service, model, base URL, requested count, deadline, and notes, and may write review notes.
  • Level 5 users (moderators): In addition to the above, they may view the site-wide request log (metadata of all users' API calls: time, model, service, status, error code, and error detail) and its statistics charts. Error details are sanitized (addresses, domains, IPs, and secrets are removed) and no export is provided. Level 5 moderators may also manage charity resources and pricing (including viewing each donation entry's source user / source text).

This means that part of your data (donation application information and request-log metadata) is visible to moderators who reach the corresponding level. Levels are configured and managed by the Operator; we recommend granting elevated levels only to trusted individuals. Moderators operate on the user site (Discord login) and do not receive administrator-site privileges.

Only administrators on the separate administrator site may view activity analytics, and only as site-wide summaries, UTC daily trends, and an activation funnel. These analytics are not available to level-5 moderators and provide no individual list or export.

4. Data Storage and Security

  • All data is stored on a server controlled by the Operator (SQLite database).
  • Sensitive credentials (Dify API keys, caller keys) are stored encrypted with AES-256-GCM.
  • Each raw request log is retained on its own strict rolling 30-day schedule, whether or not it is linked to a charity donation or that donation still exists. Reads, statistics, and exports are also limited to that window at request time. On expiry, the log and any bound alert are automatically purged.
  • User-level daily activity aggregates are retained for up to 400 days, are included in your data export, and are deleted when you delete your account.
  • Irreversible site-wide anonymous statistical snapshots, with k=5 suppression and no identifier or individual-filtering dimension, are retained for up to 400 days. They may remain after a related account is deleted, cannot be used to recover that account's activity, and are not used for decisions about an individual's access, pricing, suspension, or other treatment.
  • Settled charity accounting records (committed or refunded) are retained on a rolling 30-day schedule for short-term reconciliation. Incomplete records normally exist only while a call is in flight; after an abrupt stop they may remain until settlement is automatically recovered on service restart.
  • We take reasonable technical and administrative measures to protect your data security.

5.1 Data Transfers Necessary for Service Operation

To provide the API routing service, your message content (including text and images) may be transmitted to:

  • The Dify Workflow application you have bound (or the charity pool Dify App you choose to use);
  • The model providers configured for those Dify Apps (such as Anthropic, OpenAI, etc.), which may further process the transmitted content.

This processing is necessary for the operation of this Service. We recommend that you review the privacy policies of the Dify Apps and model providers you select.

6. Data Breach Notification

While we take reasonable security measures (including AES-256-GCM credential encryption and separate key storage), no system is absolutely secure. If we discover a security incident involving your personal information (such as unauthorized access to the database file), we will:

  • Promptly investigate and contain the scope of the incident as reasonably practicable;
  • Notify affected users as required by applicable law (via a site announcement or available contact methods);
  • If encrypted credentials are compromised, recommend that you immediately rotate the relevant API keys on the Dify platform and reset your caller key on this Service;
  • Report to relevant regulatory authorities as required by applicable law (if applicable).

  • Right of Access: You can download the data we hold about you in one click via the "Export My Data" function in the web console (including user profile, App configurations with decrypted Dify API keys, caller keys, complete request log fields, donation applications, charity settlement records, and user-level daily activity aggregates).
